CHECKER LIMITATION — found 2026-08-26, documented so it is not rediscovered
================================================================================

A URL can be HTTP 200, same host, same path, no redirect — and still be dead as a
citation, because the CONTENT was replaced.

Confirmed case: https://shattered.io/
  - 2017: the SHA-1 first-collision announcement by Stevens et al.
  - 2026: a content farm ("Kubernetes vs Docker", "Fortnite Ranks", "Clash Royale
    Gems"), which KEPT the "Shattered" branding and a "Cryptography" category.

This defeats every heuristic in check-links.py (status code, redirect-to-homepage,
offsite-redirect) AND defeats a naive keyword grep — grepping the page for "SHA-1"
returns a match, because the nav bar still says Cryptography.

Only reading the page catches it. The rule for authors:
  * cite the durable primary artifact (IACR ePrint, arXiv, a tagged repo permalink)
    over a project marketing site, which can be sold or repurposed;
  * when checking a source, read the BODY, not the status line.

check-links.py cannot detect this class. It is a human review item, and the
`blocked` bucket is not the only place that needs eyes.
